# Curio｜食物探索等級與廚師收藏

測試網址：https://yiguo12.github.io/curio/

## 完整操作

1. 新增餐點，確認食物與份量；手動新增與示範餐點都支援。
2. 餐前設定會自動安排已收藏且與本餐食物相關的廚師。也能指定其他已收藏廚師或 Curio 好奇夥伴，設定會供下一餐沿用。
3. 用餐中可以選擇本餐的不同食物，分別記錄觀察、聞一聞、碰觸、嘗試。此時只留紀錄，不顯示升級或獎勵。
4. 餐後確認食量與探索事件，按「儲存回顧」結算。每種食物各自更新進度；新解鎖才播放一次溫和登場，呈現「下次吃飯，我也會來陪你探索！」。
5. 「探索」分頁就是「我的食物廚師」收藏頁，支援全部／已解鎖／尚未解鎖。點食物查看獨立等級、進度、下一階段邀請、角色與有來源的探索歷程。
6. 下一餐選擇已收藏角色，開始後會實際出現在計時光圈與餐盤互動預覽。實體設備仍未串接。

## 示範規則集中設定

`src/exploration-config.ts`：

- 等級門檻：0、2、4、8、12 點（Lv.1–5）。
- 到 Lv.3（4 點）解鎖對應食物廚師。
- 觀察、聞一聞、碰觸、嘗試，每次有效行為各 1 點。
- 同一食物、同行為每天最多累積 1 次，跨餐與不同事件來源共用上限。
- 示範事件可累積原型經驗，來源保留；正式規則可替換。
- 不要求一定要嘗試或吃下：例如在四個不同日子觀察同一食物，也能解鎖。

上述是可調原型設定，不是兒童發展標準。沒有排行榜、扣分或吃完解鎖條件。

## 一致性與防重複

`src/exploration.ts` 將食物名稱正規化，例如胡蘿蔔與紅蘿蔔為同一食物；番茄、花椰菜等維持獨立進度。手動新增的其他食物也有獨立識別、進度與對應暫用廚師。

只有儲存餐後回顧才以 mealId 覆寫該餐探索快照，再從快照重算；食量與探索完全分開。相同事件 id 去重，行為每日上限另行限制。快速連點在寫入時也會重新核對最新 state。

- 修改備註、食量或重存同一餐不重複累積、不重播解鎖。
- 移除事件、修正日期／食物或刪除整餐，會重算探索進度。
- 已加入收藏的角色保留，不因修正紀錄被收回，亦不會再次觸發同一解鎖。
- 解鎖授予、已公告時間、進度、事件快照與陪伴設定均保存在原本的 `curio-parent-v1` localStorage。
- 儲存回顧會先驗證本機寫入成功，再顯示解鎖；重新整理不重播登場動畫。
- 舊版已完成餐後回顧會遷移，正在用餐或尚未儲存的回顧不提前計入。既有達標者安靜加入收藏。
- session 保存實際登場的 companionChefId，暫停、頁面切換與重新整理仍使用同一角色。

## IP 與動態

六種水果沿用原始 IP 靜態裁切。番茄、花椰菜、胡蘿蔔及尚無原圖的食物，採用清楚標示的暫用向量造型：無手、大小眼、小腳、超大米白廚師帽；不宣稱是最終角色資產。未解鎖收藏以透明向量剪影與線索呈現。登場只有短暫、輕柔的位移與縮放，遵守 prefers-reduced-motion；不是逐格動畫。

## 驗證與限制

`npm test`：34 項測試通過（原有 9 項，加上探索計算、遷移、防刷、一致性與元件渲染）。`npm run build`：TypeScript 與正式建置通過。

包含：每食物獨立、同事件／跨餐／來源／別名去重、只靠觀察也可解鎖、重存與修正不重複授予、收藏保留、自動優先本餐／手選其他食物角色、未解鎖不可選、保存讀回與 session 計時、舊資料遷移、角色與選單伺服器渲染。

目前環境無可用的瀏覽器控制，尚未完成實機手機／桌面截圖與點擊驗證。沒有真實 AI 辨識或設備串接。

## 啟動

已附 dist 時直接執行 `node serve.mjs`，或雙擊 Start-Curio.cmd，再開啟 http://127.0.0.1:5199/。

```sh
npm install
npm test
npm run build
npm start
```

GitHub 版本原始碼位於 curio/source/，靜態網站位於 curio/。每位測試者的資料只保存在自己的瀏覽器，沒有雲端同步。更新不更換儲存 key，不需要清除既有資料。
